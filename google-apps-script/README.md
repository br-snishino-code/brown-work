# スプレッドシート用のスクリプト

## shift-import.gs — シフト希望の取り込み

Brown Work に提出されたシフト希望を、スタッフシフトのスプレッドシートへ取り込みます。

### 準備（初回のみ）

1. Supabase に合言葉を設定する

   ```
   supabase secrets set SHIFT_EXPORT_KEY=<好きな長い文字列>
   supabase functions deploy shift-requests-export --no-verify-jwt
   ```

2. スプレッドシートを開き、「拡張機能」→「Apps Script」
3. `Code.gs` の中身を消し、`shift-import.gs` の内容を貼り付けて保存
4. スプレッドシートを再読み込みすると「Brown Work」メニューが出ます
5. 「Brown Work」→「接続の設定」で、接続先（`https://xxxxxxxx.supabase.co`）と合言葉を入力

### 翌月のファイルを複製で作ったとき

設定は隠しシート `_BrownWork設定` に保存されるため、ファイルを複製すると一緒についてきます。
ただし**合言葉と自動実行の設定だけは引き継がれません**（Googleの仕様）。

複製したら「Brown Work」→「複製したファイルの初期設定」を一度押してください。
合言葉の入力を求められ、自動実行も前月と同じ間隔で作り直されます。
前月分の取り込み記録もここで消えるので、新しい月として送り直せます。

### 使い方

- 「Brown Work」→「シフト希望を取り込む」→ 対象月を入力
- 「シフト希望_2026-11」というシートに、スタッフ×日付の表が書き込まれます
- 「自動取り込みの間隔を選ぶ」で、毎朝1回（6時台）・30分おき・15分おき・5分おき から選べます
- 「自動取り込みの状態を見る」で、今の間隔と最後に動いた時刻を確認できます
- 「自動取り込みを解除」で止まります

### 自動取り込みの動き

- 前回と内容が同じときはシートを書き換えません。短い間隔にしても、見ている最中に表示が消えません
- 手動の「シフト希望を取り込む」は、変化がなくても必ず書き直します
- Google の時間指定は「その時間ちょうど」ではなく、その時間帯のどこかで動きます
- 受付期間中だけ短い間隔にして、締め切ったら「毎朝1回」に戻す使い方がおすすめです

### 確定シフトを Brown Work へ送る

スプレッドシートで組んだシフト表を、Brown Work に反映します。

- 「Brown Work」→「確定シフトを送る」
- 読み取る内容を確認する画面が出るので、問題なければ OK
- 自動取り込みを設定していれば、同じ間隔で自動でも送られます（内容が変わったときだけ）

#### 過去の月を送るとき

「確定シフトを送る」は対象月をファイル名から読み取るため、別の月を送りたいときは
**「確定シフトを送る（対象月とシートを指定）」**を使います。

1. 送りたい月を `2026-10` の形式で入力
2. 読み取るシートの名前を入力（空のまま OK を押すと「10月」のタブを探します）
3. 確認画面で シート名・対象月・読み取れた日数 を確かめて OK

ファイル名から読める月と指定した月が違うときは、確認画面の先頭に注意書きが出ます。
別の月の表を取り違えて送ると、その月の確定シフトが置き換わるため、必ず確認してください。

送信は月ごとに独立しています。10月分を送っても、すでに送った11月分は変わりません。
取り込むのは確定シフトの表示だけで、勤怠の打刻・月次勤怠の確定・給与には影響しません。

#### 読み取り方

- 見出し行は「1(日)」のような日付が20個以上並んだ行を自動で探します
- 見出し行が複数ある表では、見出しごとに区間を分け、セルに活動場所（店舗名）が書かれている区間を選びます。
  店舗ごとの表はセルが「●」「★」などの記号なので、スタッフごとの表と見分けられます
- 氏名の列は、見出しが「スタッフ名」「氏名」「名前」などの列を優先して探します。見つからないときは、日付より左でフルネームらしい値が多い列を選びます
- 1枚のシートに店舗ごとの表とスタッフごとの表が並んでいる場合も、氏名の列が空の行は読み飛ばします
- 自動で合わないときは「確定シフトの読み取り設定」で、シート名・氏名の列（例：E）・読み取る行（例：457-554）を指定してください。
  設定はいつでも変更でき、次に送るときから反映されます
- 対象月はファイル名（例：2026年11月スタッフ勤務シフト）から読み取ります。読み取れないときは入力を求めます
- シートは「〇月」という名前のタブを自動で探します。違う名前のときは「確定シフトのシート名を指定」で設定してください

- 見出し行に書かれていない日があるときは、他の見出し行から列を補います
- 結合セル（2日分を1マスにまとめている場合など）は、同じ値が両方の日に入ります
- 確認画面に「読み取れた日数：30／30日」と出るので、欠けがないか確認できます

#### セルの中身

| セル | 扱い |
|---|---|
| 空欄 | 休み |
| 記号だけ（● ○ ★ ☆ △ × など） | 休み |
| 調整中 など | その文言のまま活動場所として表示されます |
| 有給（×有給 など） | 有給 |
| それ以外（店舗名など） | 出勤。その文字が活動場所になります |

確定シフトでは、出勤する日に活動場所（店舗名）を書く運用のため、
文字（かな・漢字・英数字）が1つも入っていないセルは休みとして扱います。
`●` は「シフト希望では出勤可能だが、調整の結果その日は休みになった」日です。
`★` `☆` は店舗シフトを調整するための記号で、スタッフの個人シフトには出てきません。

#### 氏名の突き合わせ

Brown Work の登録氏名との完全一致です（前後の空白と全角空白は自動でそろえます）。一致しなかった氏名は送信後の画面に出るので、どちらかの表記を直してください。

退職された方は、**退職日が対象月の初日より前の場合だけ**飛ばします。
たとえば10月末に退職した方の10月分のシフトは、いまは退職済みでも取り込まれます。

### 注意

- 合言葉を知っている人は、その月のシフト希望を読み取れます。スプレッドシートの共有範囲にご注意ください
- 書き込み先は専用のシートです。既存のシフト表は書き換えません
